# Context Authority

정보가 충돌하면 다음 순서로 신뢰합니다.

1. 실행 중인 시스템의 기계 검증 가능한 사실
2. 통과하는 테스트
3. 타입 시그니처와 GHC 타입 검사 결과
4. 계약과 스키마
5. 승인된 ADR
6. 아키텍처 문서
7. 도메인 문서
8. README
9. 코드 주석
10. 과거 논의
11. AI 대화 기록

AI가 추론한 정보는 Canonical Fact가 아닙니다.

## 타입이 문서보다 위에 있는 이유

이 저장소에서 타입은 의견이 아니라 컴파일러가 강제하는 사실입니다. 예를 들어 `Todo.Api.Routes.TodoApi`의 라우트 목록과 `Todo.Api.Server.todoServer`의 핸들러 목록이 어긋나면 빌드가 실패합니다. `TodoRepository` 인스턴스가 없는 모나드에서 유스케이스를 호출할 수도 없습니다.

반면 타입이 말하지 못하는 것도 분명합니다. "왜 `archived`를 종료 상태로 두었는가", "왜 DTO를 따로 만드는가"는 타입에 없습니다. 그래서 계약, ADR, 도메인 문서가 그 위가 아니라 그 옆에서 필요합니다. 타입은 무엇이 참인지 말하고 문서는 왜 그렇게 정했는지 말합니다.

## 충돌 처리

1. 각 정보의 범위, 시점과 소유자를 확인합니다.
2. 현재 구현과 실행 가능한 검증으로 사실을 확인합니다. `cabal test all`과 `scripts/context/validate-context.sh`가 1차 도구입니다.
3. 임의로 하나를 선택하지 않고 충돌을 명시합니다.
4. 권위 있는 소유자나 승인 절차를 통해 해결합니다.
5. 해결 후 잘못된 문서를 수정하거나 폐기하고 링크를 갱신합니다.

문서가 코드보다 오래되었다는 이유만으로 문서를 지우지 않습니다. 문서가 담고 있던 의도가 여전히 유효한지 먼저 확인합니다. 코드가 의도를 벗어난 것일 수도 있습니다.

데이터 손실, 파괴적 마이그레이션, 개인 정보 처리처럼 되돌리기 어려운 영역은 권위가 불명확한 상태에서 추측으로 진행하지 않습니다.
