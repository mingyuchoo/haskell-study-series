# 문체 및 형식 정책

## 언어와 용어

- 사용자·제품 문서는 한국어로 작성하며, 코드 식별자와 API 상태값은 원문 영문을 유지한다.
- `Task`는 업무 단위, `Outcome`은 승인된 업무를 조립한 결과물, `Task Owner`는 제출 담당자, `Outcome Owner`는 검토·Outcome 담당자로 일관되게 표기한다.
- 상태 라벨은 `Draft`, `Reviewed`, `Submitted`, `Approved`, `Effective` 순서를 유지한다. UI 문서에는 필요한 경우 초안, 검토 완료, 제출됨, 승인됨, 효력 발생을 병기한다.

## 코드

- Haskell은 Fourmolu 설정(`fourmolu.yaml`)을 따르고 `-Wall` 경고를 새로 만들지 않는다.
- Elm은 `elm-format`을 따르며, 순수 규칙과 HTTP·화면 표현을 계층에 맞게 분리한다.
- 이름은 도메인 의미를 우선한다. `TaskItem`, `TaskInput`, `OutcomeInput`의 필드를 바꾸면 Haskell JSON과 Elm 타입을 함께 검토한다.
- 주석은 구현을 반복하지 말고 의도·제약·이유를 설명한다.

## Markdown

- 문서는 제목 하나로 시작하고, 목적·가정 또는 제약·근거를 필요한 범위에서 명시한다.
- 표는 비교·계약·역할 매핑에만 사용하고, 긴 설명은 짧은 문단과 목록으로 쓴다.
- 코드 경로와 실행 명령은 백틱으로 표기한다. 외부 사실은 URL과 접근일을 함께 남긴다.

## 작업 기록

- 작업 상태는 `logs/STATE.md`만 단일 진실 원천으로 사용한다.
- 각 위임·산출물·검토·에스컬레이션은 `logs/<task-id>/`에 시간순으로 기록한다.
- 실패와 미검증 항목은 성공처럼 표현하지 않고, 원인·영향·다음 조치를 적는다.
