# 안전 및 권한 정책

## 권한 등급

| 등급 | 범위 | 예시 | 기본 처리 |
| --- | --- | --- | --- |
| L0 | 읽기 | 코드·로그·문서 조회, 로컬 테스트 결과 확인 | 허용 |
| L1 | 작업 공간 변경 | 소스·테스트·문서 수정, 로컬 빌드 산출물 생성 | 요청 범위 안에서 허용 |
| L2 | 외부 영향 | 배포, 이메일·메시지 전송, 외부 API 쓰기, 공유 저장소 게시 | safety 검토와 사람의 명시적 승인 필요 |
| L3 | 금지 | 결제, 자격 증명 입력·공유, 영구 삭제, 보안 통제 약화 | 에이전트가 실행하지 않음 |

## 저장소 특화 규칙

- `scripts/run.sh`는 포트 3000(또는 `PORT`)의 기존 `GeneralService-exe`를 종료할 수 있다. 실행 전 현재 서버의 소유·영향을 확인하고, 비대상 프로세스는 종료하지 않는다.
- 메모리 저장소는 재시작 시 데이터를 잃는다. 영속 저장소로 교체하거나 초기 데이터를 바꾸는 작업은 복구·마이그레이션 계획을 먼저 검토한다.
- 요청 본문의 `taskOwner`·`outcomeOwner`는 인증된 신원이 아니다. 이 값만으로 민감 작업의 인가를 주장하지 않는다.
- 외부 접근 가능한 환경에서는 인증, HTTPS, 입력·요청 크기 제한, 감사 로그 없이 배포하지 않는다.

## 비밀정보와 데이터

- 비밀 키, 토큰, 쿠키, 개인식별정보를 코드·문서·작업 로그·테스트 출력에 기록하지 않는다.
- 필요한 오류 보고에는 값 전체 대신 마스킹된 식별자와 최소한의 재현 정보를 사용한다.

## 사람 확인 형식

되돌릴 수 없거나 외부 영향이 있는 작업은 대상, 실행 내용, 복구 가능성, 미승인 시 대안을 포함해 한 가지 명확한 질문으로 승인받는다.
