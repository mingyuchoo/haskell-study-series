# Acceptance Tests

## 전제 조건

- 서버가 실행 중이고 브라우저에서 애플리케이션에 접근할 수 있다.
- 테스트 전용 `DATABASE_PATH`를 사용하고 초기 예시 Task 또는 테스트용 Task가 존재한다.
- 운영 DB 파일을 인수 테스트 대상으로 직접 사용하지 않는다.

## Task 생성

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| AT-01 | 필수 필드를 채워 Task를 생성한다. | Task가 생성되고 상태는 항상 `Draft`다. |
| AT-02 | 제목 없이 Task를 생성한다. | 생성되지 않고 제목 필수 오류가 표시된다. |
| AT-03 | 기대 결과물 없이 Task를 생성한다. | 생성되지 않고 기대 결과물 필수 오류가 표시된다. |
| AT-04 | 네 가지 긴급도·중요도 조합으로 생성한다. | 각각 즉시 실행, 계획 수립, 위임, 제거 우선순위가 표시된다. |

## 상태와 결과물

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| AT-05 | 칸반 카드의 상태를 변경한다. | 해당 Task가 선택한 상태 컬럼으로 이동하고 새로고침 및 정상적인 서버 재시작 뒤에도 반영된다. |
| AT-06 | 올바른 Task Owner로 빈 결과물을 제출한다. | 제출이 거부되고 상태가 바뀌지 않는다. |
| AT-07 | 올바른 Task Owner가 결과물을 제출한다. | 결과물이 저장되고 상태가 `Submitted`가 된다. |
| AT-08 | 다른 이름의 Task Owner로 결과물을 제출한다. | 제출이 거부된다. |
| AT-09 | 올바른 Outcome Owner가 제출된 결과물을 승인한다. | 상태가 `Approved`가 되고 선택적 검토 코멘트가 저장된다. |
| AT-10 | 올바른 Outcome Owner가 수정 요청한다. | 상태가 `Reviewed`가 되고 수정 요청 코멘트가 표시된다. |
| AT-11 | 제출 전 또는 제출자가 아닌 사용자가 승인한다. | 요청이 거부되고 상태가 바뀌지 않는다. |

## Outcome과 UI

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |

| AT-15 | 성공 또는 실패 동작을 수행한다. | 토스트 메시지가 표시되고 약 3초 뒤 사라진다. |
| AT-16 | 좁은 화면에서 보드를 연다. | 콘텐츠가 세로 레이아웃으로 읽기 쉽게 재배치된다. |

## 인증과 영속성

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| AT-17 | 회원가입 후 서버를 정상 종료하고 같은 DB로 다시 실행한다. | 계정이 유지되고 만료 전 세션 토큰으로 내 프로필을 조회할 수 있다. |
| AT-18 | 생성 후 24시간이 지난 세션 토큰으로 내 프로필을 조회한다. | 인증이 거부되고 만료된 세션이 삭제된다. |
| AT-19 | Task와 승인된 Outcome을 만든 뒤 같은 DB로 서버를 다시 실행한다. | Task의 결과물·검토 코멘트와 Outcome의 Task ID·결과물 순서가 유지된다. |
| AT-20 | `SEED_EXAMPLE_DATA=true`로 빈 DB에서 서버를 두 번 실행한다. | 예시 Task는 최초 한 번만 추가되고 중복 생성되지 않는다. |
| AT-21 | Task가 이미 있는 DB를 처음 연다. | 예시 Task를 추가하지 않고 기존 데이터를 유지한다. |
| AT-22 | 서버 지원 버전보다 높은 값을 `schema_migrations`에 둔 테스트 DB를 연다. | 새 스키마 마이그레이션을 적용하지 않고 시작을 거부한다. |
| AT-23 | SQLite `.backup`으로 백업하고 별도 테스트 경로에 복원한다. | `PRAGMA integrity_check`가 `ok`이고 주요 Task·Outcome·사용자 데이터가 일치한다. |
| AT-24 | `SEED_EXAMPLE_DATA=false`로 빈 DB에서 서버를 실행한다. | 스키마만 준비되고 예시 Task는 생성되지 않는다. |

## 비기능 확인

- `DATABASE_PATH`를 지정하지 않으면 작업 디렉터리의 `general-service.sqlite3`를 사용하고, 빈 값이면 시작을 거부하는지 확인한다.
- 과거 메모리 저장소의 데이터가 SQLite로 자동 이관되지 않음을 전환 계획에서 확인한다.
- 같은 SQLite 파일은 단일 서버 인스턴스에서만 사용하고 다중 인스턴스·공유 파일시스템 구성을 인수하지 않는다.
- 운영 DB 적용 전 백업, 무결성 검사, 별도 경로 복원 리허설과 사람 승인을 확인한다.
- API가 잘못된 Task ID에 `400`, 존재하지 않는 Task에 `404`를 반환하는지 확인한다.
- `stack test`가 통과하는지 확인한다.
