# Acceptance Tests

## 전제 조건

- 서버가 실행 중이고 브라우저에서 애플리케이션에 접근할 수 있다.
- 초기 예시 Task 또는 테스트용 Task가 존재한다.

## Task 생성

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| AT-01 | 필수 필드를 채워 Task를 생성한다. | Task가 생성되고 상태는 항상 `Draft`다. |
| AT-02 | 제목 없이 Task를 생성한다. | 생성되지 않고 제목 필수 오류가 표시된다. |
| AT-03 | 기대 결과물 없이 Task를 생성한다. | 생성되지 않고 기대 결과물 필수 오류가 표시된다. |
| AT-04 | 네 가지 긴급도·중요도 조합으로 생성한다. | 각각 즉시 실행, 계획 수립, 위임, 제거 우선순위가 표시된다. |

## 상태와 결과물

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| AT-05 | 칸반 카드의 상태를 변경한다. | 해당 Task가 선택한 상태 컬럼으로 이동하고 새로고침 뒤에도 서버 실행 중에는 반영된다. |
| AT-06 | 올바른 Task Owner로 빈 결과물을 제출한다. | 제출이 거부되고 상태가 바뀌지 않는다. |
| AT-07 | 올바른 Task Owner가 결과물을 제출한다. | 결과물이 저장되고 상태가 `Submitted`가 된다. |
| AT-08 | 다른 이름의 Task Owner로 결과물을 제출한다. | 제출이 거부된다. |
| AT-09 | 올바른 Outcome Owner가 제출된 결과물을 승인한다. | 상태가 `Approved`가 되고 선택적 검토 코멘트가 저장된다. |
| AT-10 | 올바른 Outcome Owner가 수정 요청한다. | 상태가 `Reviewed`가 되고 수정 요청 코멘트가 표시된다. |
| AT-11 | 제출 전 또는 제출자가 아닌 사용자가 승인한다. | 요청이 거부되고 상태가 바뀌지 않는다. |

## Outcome과 UI

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| AT-12 | 같은 Outcome Owner의 승인 Task를 하나 이상 선택해 Outcome을 생성한다. | `Effective` 상태의 Outcome이 생성되고 Task ID와 제출 결과물이 포함된다. |
| AT-13 | 미승인 Task 또는 다른 Outcome Owner의 Task를 Outcome에 포함한다. | Outcome 생성이 거부된다. |
| AT-14 | 카드 제목 또는 상세 보기로 상세 패널을 연다. | 전체 설명과 결과물 처리 동작이 표시된다. |
| AT-15 | 성공 또는 실패 동작을 수행한다. | 토스트 메시지가 표시되고 약 3초 뒤 사라진다. |
| AT-16 | 좁은 화면에서 보드를 연다. | 콘텐츠가 세로 레이아웃으로 읽기 쉽게 재배치된다. |

## 비기능 확인

- 서버를 재시작하면 메모리 데이터가 초기화되는 것을 확인한다.
- API가 잘못된 Task ID에 `400`, 존재하지 않는 Task에 `404`를 반환하는지 확인한다.
- `stack test`가 통과하는지 확인한다.
