# UX

## 화면 목적

관리자가 Task의 우선순위와 진행 상태를 한 화면에서 이해하고, 세부 업무·결과물 검토·Outcome 조립까지 이어서 처리할 수 있게 한다.

## 주요 인터랙션

| 영역 | 동작 |
| --- | --- |
| 생성 폼 | 긴급도, 중요도, 제목, 기대 결과물, 설명, Task Owner, Outcome Owner 순서로 입력한다. |
| 칸반 보드 | `Draft`, `Reviewed`, `Submitted`, `Approved`, `Effective` 컬럼에서 Task를 확인하고 드래그로 상태를 변경한다. |
| Task 카드 | 제목, 우선순위, 결과물 진행 상태와 설명 요약을 표시한다. |
| 상세 패널 | 전체 설명, 수정·삭제, 결과물 제출, 승인·수정 요청을 제공한다. |
| 알림 | 성공·실패 메시지를 토스트로 표시하고 약 3초 후 자동으로 숨긴다. |

## 표현 원칙

- 상태 값은 한국어로 표시하되 API의 영문 열거형과 명확히 매핑한다.
- 카드에는 요약만 두고 상세 정보는 패널에서 보여 정보 밀도를 조절한다.
- 넓은 화면에서는 사이드바를 활용하고, 좁은 화면(약 700px 이하)에서는 세로 레이아웃으로 전환한다.
- 색상만으로 상태를 구분하지 않고 텍스트 레이블을 함께 제공한다.

## 접근성과 후속 개선

- 드래그 앤 드롭과 동일한 상태 변경을 키보드·버튼으로도 제공해야 한다.
- 폼 필드에 연결된 오류 메시지와 명확한 포커스 상태를 유지해야 한다.
- 상태 이동과 삭제 같은 중요한 동작에는 취소·복구 가능한 피드백을 검토한다.
