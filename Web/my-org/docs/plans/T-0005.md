# T-0005: 선택 저장소를 SQLite로 전환

## 요청과 유지 조건

기본 JSON 파일 저장(`runs/local/events.json`, `MY_ORG_EVENT_FILE`)을 유지하고 선택 PostgreSQL 저장소를 SQLite로 교체한다. 데모 모드는 DB 설정과 무관하게 `runs/demo/events.json`을 사용한다. 기존 JSON 이벤트 형식과 도메인·HTTP 동작은 유지하며 사용자 데이터 또는 기존 PostgreSQL DB의 자동 마이그레이션은 하지 않는다.

## 확인한 사실

- 저장소 및 상위 경로와 조사한 하위 경로에서 실제 `AGENTS.md` 파일을 찾지 못했다. 사용자 제공 규약을 적용한다. `shared/schemas/handoff.json` 및 `workflows/default.yaml`도 없다.
- `src/Lib.hs`는 데모가 아닐 때 `MY_ORG_TEST_DATABASE_URL`이 있으면 PostgreSQL을 선택하고 나머지는 JSON을 사용한다.
- `src/MyOrg/Store.hs`는 Runtime과 영속성 어댑터를 조립한다. PostgreSQL 어댑터는 이벤트 JSON을 `my_org_events`에 보관하고 세션 advisory lock으로 단일 서버를 강제한다.
- `package.yaml`에 `postgresql-simple`이 있고 `my-org.cabal`은 Hpack 산출물이다. Stack snapshot은 기존 설정을 유지할 수 있다.
- `Makefile`의 demo 명령 및 `test/StartupSmokeSpec.hs` 환경 격리가 PostgreSQL 환경 변수 이름에 의존한다. README에는 선택 저장소·데모·아키텍처·논리 삭제 설명에 PostgreSQL이 있다.

## 구현 계획

1. coder가 `Infrastructure.SQLiteStore` 및 `openSQLiteStore :: FilePath -> IO Store`로 선택 DB 조립을 교체한다. 환경 변수는 파일 경로 의미가 명확한 `MY_ORG_SQLITE_FILE`을 사용한다. 미설정 기본 JSON 및 데모 우선순위를 유지한다.
2. SQLite에 이벤트 순번과 기존 JSON payload를 저장하고 배치 추가를 트랜잭션으로 처리한다. 열기·읽기 실패 시 자원을 정리하고, 같은 DB에 여러 서버가 각자의 메모리 projection을 유지하며 쓰는 상황을 차단하는 단일 서버 잠금을 보존한다. SQLite 파일 경로 부모 생성 및 잠금 방식·제약을 문서와 일치시킨다.
3. coder가 사용자 요청에 필요한 의존성을 `postgresql-simple`에서 `sqlite-simple`로 교체하고 Hpack 산출물 및 demo 명령을 갱신한다. 이는 요청한 DB 교체에 필요한 의존성 변경이며 무관한 의존성/버전은 변경하지 않는다.
4. 관련 현재 문서에서 환경 변수, 실행 예시, 별도 DB 서버 불필요, 파일 잠금/복구 제약, DB 저장 구조와 기존 JSON 유지 동작을 수정한다. 과거 완료 이력을 현재 구현으로 오해하지 않게 필요한 설명을 추가하며 역사적 기록은 임의 재작성하지 않는다.

## 검증과 완료 기준

- 임시 SQLite 파일에서 조직/이벤트 저장 후 닫고 재개방했을 때 동일 audit와 projection이 복구된다.
- 여러 이벤트를 한 번에 저장하다 실패해도 일부만 반영되지 않는다. 저장 실패 시 Runtime 메모리도 유지된다.
- 동일 DB 두 번째 열기는 거절되고 정상 닫기 및 초기화 실패 후 잠금·연결이 해제된다. 손상된 payload 및 불연속 이벤트 순번은 시작을 거절한다.
- 프로세스 시작 테스트에서 미설정 기본 JSON, 명시 SQLite 선택/재시작, 데모의 SQLite 설정 무시를 검증한다. 기존 환경 변수 격리도 새 설정을 포함하도록 갱신한다.
- 기존 JSON fixture와 HTTP 계약은 그대로 유지하며 `make test`, `make lint`, `git diff --check`를 실행한다. 테스트는 임시 디렉터리만 사용한다.
- tester 결과 통과 및 reviewer 승인 후 orchestrator가 완료한다.

planner는 계획 작성 후 문서 담당 역할로 `README.md`, `CHANGELOG.md`, `STATE.md`를 갱신한다. coder는 소스·필수 패키지/빌드 설정, tester는 실제 `test/` 테스트 작성과 실행, reviewer는 읽기 전용 검토를 담당하도록 orchestrator가 경로를 배정했다. 공통 규약의 예시 경로(`tests/`)와 저장소의 실제 경로(`test/`) 차이는 현재 저장소 구조에 맞춘다.

## 승인 후 결정

- 단일 서버 잠금은 SQLite의 `locking_mode=EXCLUSIVE`, `journal_mode=DELETE` 및 최초 exclusive transaction으로 확보한다. 별도 `.lock` 디렉터리는 만들지 않으며 프로세스 종료 시 SQLite 잠금이 해제된다.
