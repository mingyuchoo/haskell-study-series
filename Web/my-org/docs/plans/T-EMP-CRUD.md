# T-EMP-CRUD 구성원 관리 구현 계획

## 확인된 현황

- 사용자 요청은 구성원 독립 메뉴, 목록·검색·등록·상세·이름/역할 수정, 비활성화 및 신규 배정 제외, 목표 인계 규칙, 부서·이메일·재직 상태 확장을 포함한다.
- Haskell 도메인/API는 src/, Elm 화면은 static/src/, 테스트는 test/와 static/tests/에 있다. 해당 경로 및 docs/에서 추가 AGENTS.md는 발견되지 않았다.
- Person은 ID·이름·역할·보고 대상만 가지며 AddPerson과 PersonAdded만 존재한다. 현재 이벤트 저장/재생 구조를 유지한다.
- Decision에는 완료 상태가 없다. 목표 책임, 회고 결정 담당자, reportsTo가 구성원에 연결된다.
- make test는 Elm 테스트·경계/형식 검사·컴파일과 stack test를 실행한다. make lint는 Haskell 경고를 오류로 검사한다.

## 구현 정책

1. Person의 기존 이벤트 구조를 유지하는 선택 profile 확장에 department/email과 재직 상태(active/inactive)를 추가한다. 기존 JSON 및 저장 이벤트에서 새 필드가 생략되면 빈 선택값과 active로 읽어 하위 호환을 보장한다. 이름/역할은 공백 불가, 이메일/부서는 선택 입력으로 정규화한다.
2. 구성원 목록은 재직/비활성 상태 모두 조회 가능하며 이름·역할·부서·이메일 검색 및 상태 필터를 제공한다. 상세에서 기본정보, 보고 대상, 재직 상태, 담당 목표를 확인하고 수정한다. ID는 수정하지 않는다.
3. 비활성화 시 담당 목표 또는 직속 보고자가 남아 있으면 다른 활성 구성원을 명시적으로 지정한다. 연결이 없으면 인계 대상 없이 비활성화할 수 있다. 자기 자신·없는 사용자·비활성 사용자는 인계 대상이 될 수 없다.
4. 비활성화와 목표·보고관계 인계는 단일 명령/이벤트에서 원자적으로 적용한다. 과거 회고는 당시 결정/평가 스냅샷이므로 결정 담당자를 소급 변경하지 않는다. 원본 저장 이벤트, 기존 결과 보고자, 회고 결과 스냅샷 및 감사 행위자 정보는 보존하고 과거 담당자의 비활성 상태를 화면에 표시한다.
5. 인계로 보고 관계 순환 또는 자기 보고가 생기는 경우를 방지한다. 직속 보고자를 후임으로 지정하면 후임의 보고 대상은 퇴직자의 상위 보고자로 올린 후 나머지 직속 보고자를 후임에게 연결한다. 일반 수정도 순환/비활성 보고 대상 연결을 거부한다.
6. 비활성 구성원에게 목표 책임·권한·새 회고 결정·새 보고관계를 부여할 수 없고 결과 보고자로 새 기록을 제출할 수 없도록 서버에서 검증한다. UI 선택지에서도 제외한다. 과거 기록 표시를 위해 전체 구성원 이름 조회는 유지한다.
7. 권한/예산은 후임에게 자동 복사하지 않는다. 이관된 목표는 기존 책임자 변경 정책처럼 초안으로 돌려 권한 확인 후 재활성화하도록 하며 이를 화면에 명시한다. 재활성화를 제공하는 경우 이전 담당 배정을 자동 복원하지 않는다.

## 작업 분배 및 잠금

- orchestrator: 계획 승인, 소유 경로별 잠금, 결과 취합. 직접 코드 수정 없음.
- coder: src/와 static/src/ 구현. 실제 저장소 경로에 맞는 테스트 생성자/fixture 호환 수정이 필요하면 tester와 조정. static/src/는 사용자 요청의 화면 구현에 필수인 애플리케이션 소스 경로로 취급하도록 orchestrator가 배정한다.
- tester: test/와 static/tests/ 검증 작성 및 실행. 기존 test/ 경로를 규약의 tests/에 대응시킨다.
- reviewer: 변경 및 인계 정합성, 역사 보존, 호환성, UI 사용성 검토. 읽기 전용.
- 의존성 추가/버전 변경, git push, 실제 데이터 마이그레이션은 하지 않는다.

## 변경 지점

- Domain/Organization: 프로필/상태 타입과 기본값.
- Application, Domain/Event 및 적용기: 수정/비활성화 명령, 검증, 원자적 인계 이벤트.
- Serialization/JSON, Http/Route 및 조회 DTO: 새 필드, 이전 이벤트 호환, 조직 범위 API.
- Elm Domain/Api/Form/Page/Main: 구성원 메뉴, 목록/검색/상세/등록/수정/비활성화 폼 및 활성 구성원 선택지.
- 기존 Person 이벤트/fixture를 유지하며 profile 확장을 Wire/Contract 및 UI 디코더에 일관되게 반영.

## 검증 및 완료 조건

- 등록 → 목록 검색 → 상세 수정 → 재조회 → 비활성화/인계가 동작한다.
- 담당 목표 및 보고관계가 후임에게 한 번에 이동하고, 실패 시 부분 변경이 없다.
- 비활성 구성원의 신규 배정/권한/결정/보고가 서버에서 거부되고 UI 선택지에서 제외된다.
- 과거 결과 및 감사 기록은 원래 구성원을 참조하고 비활성 구성원은 목록/상세에서 확인 가능하다.
- 없는 구성원/다른 조직/자기 인계/비활성 후임/필수 인계 누락/보고 순환을 검증한다.
- 기존 필드만 있는 PersonAdded 이벤트 재생 및 새 이벤트 저장 후 재시작이 동일 상태를 만든다.
- make test, make lint, npm run build를 실행하고 필요한 형식을 정리한다. 실패는 숨기지 않으며 같은 원인 3회 실패 시 규약에 맞춰 보고한다.
- tester 통과 및 reviewer 승인 후 완료한다.
