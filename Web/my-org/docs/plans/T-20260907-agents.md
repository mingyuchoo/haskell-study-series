# T-20260907-agents: 멀티 에이전트 모델링 권고안 구현

## 확인한 사실
- T-20260907-001 분석에서 에이전트가 도메인 개념으로 존재하지 않고 Elm 카드 표현에 그친다는 점, 업무 흐름의 인계·승인·담당이 자유 텍스트라는 점, 데모에 업무 흐름이 없고 내보내기가 없다는 점, StartupSmokeSpec이 간헐적으로 실패한다는 점을 확인했다.
- .claude/agents/ 정의가 없어 서브에이전트 위임과 reviewer 검토를 규약상 수행할 수 없으므로 orchestrator가 직접 구현하고 검증한다.

## 구현 결정
1. 도메인: `Domain.Agent`에 PermissionLevel(L0~L3), ApprovalBy(구성원 또는 결정 권한), AgentRole을 두고 `AgentRolesSaved [AgentRole]` 이벤트로 목록 전체를 저장한다. 설계 저장은 실행 권한이나 도구 접근을 부여하지 않는다.
2. 도출과 진단: `Domain.AgentDraft.deriveAgents`는 업무 흐름마다 하나의 후보를 결정적으로 만들고 참조 필드를 텍스트보다 우선한다. `diagnoseAgents`는 초안과 저장된 설계에 A001~A009를 같은 규칙으로 적용하며 Compiler의 Severity를 재사용한다.
3. 참조 필드: Workflow에 rolePerson, approvalPerson, approvalPermission, handoffWorkflows를 선택 필드로 추가한다. 비어 있으면 JSON에 나타나지 않고, 없는 구성원은 PersonNotFound(404), 자기 자신 또는 없는 업무 인계는 InvalidInput(400)이다.
4. API: `GET/POST /api/organizations/:id/agents`와 `GET .../agents/export`(text/markdown 첨부). 조회는 `AgentsResource`와 `AgentExportQuery`로 Query 계층에 두고 Http.Encode가 JSON 또는 텍스트를 선택한다.
5. 화면: Page.Agents가 초안·진단·설계안 편집·저장·내보내기 링크를 담당하고 조직 진단의 검토 폼을 아래에 재사용한다. Ui.AgentGraph는 인계 관계를 층으로 나눈 SVG와 관계 목록을 그린다. App.Agents는 App.Discovery와 같은 저장본·초안·버전 충돌 규칙을 따른다.
6. 데모와 호환: demoCommands는 원래 51개 시나리오(demoCoreCommands) 뒤에 SaveDiscovery 한 건을 붙인다. 고정 fixture와 구형 데모 인식은 legacyDemoEvents(52개)로 유지한다. 체험 가이드에 5단계를 추가한다.
7. 안정성: Lib가 SIGINT와 SIGTERM에서 UserInterrupt를 던져 bracket 정리로 잠금을 해제한다. StartupSmokeSpec은 일회용 서버 정지 후 잠금 디렉터리를 정리한다.

## 검증
- Haskell: AgentSpec(도출, 텍스트 대체, 진단, 명령 검증, 코덱 왕복, 과거 이벤트 읽기, 내보내기), AgentsSmokeSpec(HTTP 초안·저장·409/404/400·내보내기·재개방·참조 검증), PlanSpec의 데모 이벤트 수를 시드에서 계산하도록 수정.
- Elm: AgentTest(설계 편집, 디코더, 참조 생략, 가져오기와 저장 효과, 버전 충돌, 페이지 렌더링, 층 정렬), DiscoveryTest와 DiscoveryPageTest의 참조 케이스, StateTest 효과 목록 갱신.
- make lint, npm run check, git diff --check와 임시 저장소 서버의 API 흐름 확인.
