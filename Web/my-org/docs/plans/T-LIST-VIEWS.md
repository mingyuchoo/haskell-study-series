# T-LIST-VIEWS — 메뉴별 카드 / 표 보기

## 확인한 사실
- 프런트엔드는 Elm이며 Main.elm이 페이지 상태와 폼 초안을 보유한다. API 변경 없이 구현할 수 있다.
- Organizations, People, Goals, Authorities, Results, Learning의 주요 목록은 카드이다. Responsibility의 책임 배정 목록은 이미 표이며 하단 관계 목록은 그래프 행이다.
- 구성원 상세는 선택된 ID를 Main에서 관리한다. 목표·결과·권한은 카드 내부에 작업 폼이 있으며 guide 링크가 goal-/authority-/owner- ID에 포커스한다.
- 작업 루트와 docs, docs/plans, static, static/src, static/src/Page에는 별도 AGENTS.md가 없다. 제공된 공통 규약을 적용한다.

## 구현 결정
1. Ui.ListView 같은 공용 모듈에 Cards / Table, 접근 가능한 카드/표 버튼(aria-pressed), caption과 scope를 갖춘 표 래퍼를 둔다. 메뉴별 독립 상태를 Main에 두고 메뉴 이동 및 서버 새로고침에서 보존한다. 새 브라우저 실행 영속화는 이번 범위에서 요구하지 않는다.
2. 기존 모습을 기본값으로 유지한다. 책임 메뉴는 기존 표 기본값을 유지하고 카드 선택을 추가한다. 다른 여섯 메뉴는 카드 기본값이다. 각 메뉴의 주요 목록 위에 동일한 보기 전환을 노출한다.
3. 조직: 조직명, 구분(데모/내 조직), 구성원 수, 목표 수, 등록일, 조직 열기 및 상세·수정·삭제.
4. 구성원: 이름, 역할, 부서, 이메일, 재직 상태, 담당 목표 수, 상세·수정. 기존 검색/재직 필터/선택 상세 패널/비활성화 흐름을 그대로 공유한다.
5. 목표: 목표/KPI, 최종 책임자, 현재값/목표값, 달성률, 마감, 상태, 관리. 관리 셀의 펼침 영역에 책임 지정·활성화·전략 폼을 재사용하며 결과 이동을 유지한다.
6. 책임: 목표/KPI, 최종 책임자 지정, 목표값, 필요 권한·예산·통제율, 상태를 표와 카드 양쪽에서 제공한다. 관계 그래프 및 구조 검사는 그대로 유지한다.
7. 권한: 구성원, 역할, 권한 비중, 담당 목표 수, 예산·권한 편집. 표 편집 영역에 기존 Grant 폼을 재사용하여 저장 검증과 비활성 구성원 제외 규칙을 보존한다.
8. 결과: 목표/KPI, 책임자, 현재값/목표값, 달성률, 상태, 결과 보고·평가. 펼침 영역에서 보고 폼과 최근 결과 이력을 재사용한다. 목표 이동과 평가 기록 버튼을 유지한다.
9. 학습: 회고일, 목표, 평가, 회고 요약, 학습, 다음 결정(담당자·기한), 경고. 여러 학습·결정을 생략하지 않는다. 회고 등록 및 감사 기록은 그대로 유지한다.
10. 표 래퍼의 가로 스크롤로 좁은 화면을 지원한다. 한 시점에는 카드 또는 표만 렌더링하여 폼 ID 중복을 방지한다. 가이드 포커스용 ID를 선택된 보기에서도 보존하고 숨겨진 펼침 영역 때문에 포커스가 실패하지 않도록 한다.

## 검증
- 일곱 메뉴 모두 카드/표 전환, 메뉴별 상태 독립성과 이동 후 유지, 빈 목록 및 구성원 검색을 Elm 테스트로 확인한다.
- 두 보기에서 기존 작업 메시지와 busy/fresh 비활성 규칙, 폼 초안 유지, 가이드 이동 대상 존재를 확인한다.
- make test, 필요한 프런트 빌드 및 lint를 실행한다. 데스크톱/좁은 화면에서 표 스크롤과 주요 입력 동선을 확인한다.
- 구현 완료 후 tester와 reviewer의 독립 검증을 거쳐 완료한다.
